# Durable PostgreSQL configuration import, version 0.1

`PostgresTenantConfigArchiveImporter` stages a validated, configuration-only tenant archive into a fresh PostgreSQL target tenant. It uses the same archive decoder, mapping decisions, and target restrictions as the reference importer. Host authorization and a durable audit reference precede preflight, stage, and source-history readback.

Preflight validates the complete archive and every location mapping without writing target state. Stage takes the tenant's exclusive portability lock, rechecks that the target has no import receipt or operational rows, and commits native location policies, clinic automation, published knowledge, one stopped-write state per clinic, the import receipt, and the complete validated source configuration history in one transaction. A concurrent stage with the same archive returns the first receipt; a changed digest for the same archive ID and any different archive for that target tenant are rejected. Imported booking and automation are off, executable capabilities are reduced to request-only or unavailable, and target writes are stopped. No phone route is published.

The registry keeps source write-stop and settings history beside the mapping receipt, including facts the target's native audit tables cannot express. Native policy and automation tables also receive each source version plus an audited disabling version when the source head was enabled. Published knowledge retains original version numbers, including gaps left by excluded drafts. The target's own write-stop history starts at version 1, while the source history remains available in the authorized registry read. This preserves source provenance without treating source operators as target operators. The registry itself obeys the tenant portability fence, including direct SQL writes and truncation.

`test/storage/postgres-durable-config-import.test.ts` exports a two-location source and stages it into native target tables, starts a synthetic knowledge call, checks source-history readback after constructing a new importer, checks booking and automation history, replays the archive, and rejects a different archive. A second case races two importers and refuses a target with pre-existing settings. `npm run probe:postgres` runs these against a disposable migrated database.

The importer needs an empty target tenant. It does not import calls or staff work, validate a final source fence version, publish a number route, or implement rollback. Retained-data eligibility, a buyer-owned publish barrier, and one-owner number switching remain required for Phase 4/5 exit gates.
