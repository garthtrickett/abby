# Staffed transfer windows

The host supplies `CallPolicy.staffedCoverage` and `CallPolicy.staffedIntervals` together when it enables executable live transfer. Coverage has canonical UTC `startsAt` and `endsAt` instants, with an inclusive start and exclusive end, and spans at most 72 hours. Every staffed interval must lie inside that coverage. Before admitting a call, the host expands the location's time zone, opening hours, holidays, and allowed transfer windows into the covered intervals. The call retains that versioned policy snapshot. A valid empty interval list means closed only while the call time is inside coverage. Missing, expired, malformed, or oversized evidence makes staffing unknown: Abby blocks live transfer and cannot claim staff are unavailable or append approved after-hours information. Old interval-only snapshots are unknown until a host supplies coverage. The reference policy has no live transfer destination or staffed evidence.

A clear transfer request inside a staffed interval creates a pending transfer. A request outside one creates a durable staff task and caller notice without claiming a live connection. The reducer checks the interval again when it marks a started transfer possibly sent. If the window closed meanwhile, that same ledger transition cancels the unsent transfer, requests staff follow-up, and queues a truthful notice. The transport port is not called. A transfer already marked possibly sent keeps its existing evidence rules: it cannot be called canceled just because the window later closes.

The reference host utility `expandStaffSchedule` now returns the coverage period with the intervals it expanded from a location's IANA time zone, local weekly windows, and closed local dates. It handles overnight windows, the skipped hour when daylight saving begins, and both occurrences of a repeated hour when daylight saving ends. A closed date overrides an overnight window on that local date. Invalid input returns a typed failure rather than an open interval. A call that outlives the 72-hour maximum horizon loses live-transfer permission and cannot claim a confirmed closure until the host supplies a new policy through an explicitly designed update path. The reference host must source these fields from its own approved clinic configuration; this utility does not infer them from Cliniko metadata.

When a host policy includes a location-scoped `staffSchedule` approved by a clinic owner, call admission expands it from the accepted call time through the earlier of the approval expiry and 72 hours and replaces any pre-expanded staffing evidence. A wrong-scope, expired or invalid schedule discards both the schedule and stale intervals from the admitted snapshot, leaving staffing unknown. The approved schedule version, validity period and owner remain captured with a valid call policy; reference configuration export/import maps the owner and location. This is an admission contract for an authorized host. The generic lit-html dashboard now provides a versioned clinic-admin hours control and audit through the same typed command gateway used by agents. Its synthetic admin actor supplies an approval for test calls; a participating clinic must still approve its actual hours, and standalone Cliniko still cannot enable live transfer or staff follow-up.

Synthetic full-call E2E exercises open, closed, holiday-excluded, expired, missing-coverage, and boundary-crossing windows through `VoiceSession` with both memory and PostgreSQL ledgers. Focused tests cover Sydney's 2026 spring gap and 2027 fall overlap, whose transition dates are documented by the [NSW Government](https://www.nsw.gov.au/about-nsw/daylight-saving). This does not prove live telephony or a real clinic's approved hours. Those need separate conformance evidence before caller traffic.
