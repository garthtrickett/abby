# Staffed transfer windows

The host supplies `CallPolicy.staffedIntervals` when it enables executable live transfer. Each interval has canonical UTC `startsAt` and `endsAt` instants, with an inclusive start and exclusive end. Before admitting a call, the host expands the location's time zone, opening hours, holidays, and allowed transfer windows into those intervals. The call retains that versioned policy snapshot. Missing, empty, malformed, or oversized interval lists block live transfer; the reference policy has no live transfer destination or staffed intervals. A valid empty list is currently treated as closed. Missing or malformed evidence means staffing is unknown, so caller speech cannot claim staff are unavailable or append approved after-hours information. The policy does not yet carry the expansion horizon; a call beyond that horizon could still misinterpret an empty list as confirmed closure. Bind and check the coverage interval before using closed-hours wording on long-lived calls.

A clear transfer request inside a staffed interval creates a pending transfer. A request outside one creates a durable staff task and caller notice without claiming a live connection. The reducer checks the interval again when it marks a started transfer possibly sent. If the window closed meanwhile, that same ledger transition cancels the unsent transfer, requests staff follow-up, and queues a truthful notice. The transport port is not called. A transfer already marked possibly sent keeps its existing evidence rules: it cannot be called canceled just because the window later closes.

The reference host utility `expandStaffSchedule` now expands a location's IANA time zone, local weekly windows, and closed local dates into at most 72 hours of UTC intervals. It handles overnight windows, the skipped hour when daylight saving begins, and both occurrences of a repeated hour when daylight saving ends. A closed date overrides an overnight window on that local date. Invalid input returns a typed failure rather than an open interval. The 72-hour horizon is a safety bound: a call that outlives it loses live-transfer permission until the host supplies a new policy through an explicitly designed update path. The reference host must source these fields from its own approved clinic configuration; this utility does not infer them from Cliniko metadata.

Synthetic full-call E2E exercises open, closed, holiday-excluded, and boundary-crossing windows through `VoiceSession` with both memory and PostgreSQL ledgers. Focused tests cover Sydney's 2026 spring gap and 2027 fall overlap, whose transition dates are documented by the [NSW Government](https://www.nsw.gov.au/about-nsw/daylight-saving). This does not prove live telephony or a real clinic's approved hours. Those need separate conformance evidence before caller traffic.
