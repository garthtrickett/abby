# Cliniko provisional availability in a synthetic call, version 0.1

`ClinikoAvailabilityReader` can be supplied as an `AvailabilityHost` to either text composition. The default standalone demo does not configure it. A final caller turn or authorized `availability.read.v2` agent command requests a bounded date range through the same scoped port. The adapter checks online-booking eligibility and returns a non-reservable snapshot with the business's IANA time zone and observation time.

The call transition validates scope, date range, local dates, unique timestamps, time zone, and freshness before committing a notice. It speaks at most three future times as **possible** times, explicitly says they may change, and says no appointment is reserved or confirmed. An empty result says no possible time was found for the requested dates. A disabled online-booking flag, provider fault, malformed result, stale observation, unclear speech, or absent adapter creates a fallback notice and staff work. A newer caller turn fences a late availability read. No availability result enters the booking evidence or host-write path.

Synthetic E2E uses the actual Cliniko HTTP adapter with fake provider responses, enters through `VoiceSession` final turns, and verifies queued wording, playback acknowledgment, request-only booking mode, no write, DST conversion, fallback, and stale-read fencing in both memory and PostgreSQL compositions. Agent-command journeys run through embedded and standalone compositions. The provider contract suite separately checks authentication, pagination, online flags, scope, and typed HTTP failures. The previous JSON call-state shape remains readable; a later transition adds `availabilityReads` provenance.

This does not authorize live caller use. The [current demo account probes](../phase-0/CLINIKO_EVIDENCE.md) proved the read-only adapter for two appointment types, but the business normally has online booking disabled and its configured time zone is `Asia/Jakarta`. A controlled concurrency probe then observed two same-slot synthetic appointment POSTs both return 201. Caller wording still needs product approval, and no live media or phone route has verified playback and fallback. Cliniko times are not held slots; this profile cannot rely on a fresh availability read or a provider conflict rejection to make booking safe.

The standalone policy store and composition now default their host booking mode to `unavailable`. Enabling the booking setting without an approved host-owned command and task path still leaves booking unavailable; it does not store a patient-specific staff request in Abby. Synthetic reference-host fixtures choose `execute` or `requestOnly` explicitly to test those paths. They do not authorize those modes for a standalone Cliniko clinic.
