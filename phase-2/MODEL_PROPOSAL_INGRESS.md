# Model proposal ingress

The model boundary accepts `unknown` output through `RawModelPort` and decodes it to the versioned `ModelProposal` union. A proposal is a suggestion, never a host mutation, patient proof, booking confirmation, or approved answer. The decoder rejects unknown schema versions, extra fields, missing answer evidence, duplicate source references, invalid dates, and handoff reasons that require system or host evidence. Transport exceptions and elapsed deadlines become typed failures without copying provider diagnostics into caller state.

`ModelInput` contains caller text and remains transient at this boundary. A composition must not persist it as a model effect payload until consent and retention rules authorize that storage. The current runtime does not yet schedule model effects or accept model results through the SAM loop. This contract is the ingress for that next step, not evidence of a working LLM receptionist. The fake-port tests require no model credentials and make no live model call.

The next integration must commit the final turn and a privacy-safe model task reference together, recover or fail that task after a worker restart, check the conversation revision on the result, and route answers through approved host knowledge. Action proposals must obtain host-issued patient and offer evidence and caller confirmation before a write can be planned. A model timeout, malformed result, or missing evidence must take a truthful clarification or staff path. Add a full text journey for each newly exposed model behavior before enabling it in the voice session.
