# Completed outbound notification and capacity recovery

Optional trusted-host engineering; inactive by default. A signed completed-call notification can be retained in a dedicated clinic-approved native family. It identifies a candidate call, without asserting its end time or the person's speech, consent, opt-out, patient identity or clinical outcome. Independent provider and source evidence can then release only the original physical call-capacity allocation. The separate contact hold remains unresolved.

## Original selection and one permanent purpose

An explicit terminalObservationBinding is part of the original conversation profile only when selected. It covers the native family, policy, physical API credential, verifier key and effective native deadline. Legacy profile digests remain unchanged and cannot silently acquire a new notification producer. The producer reauthenticates the raw signed status request with the actual runtime account and sealed original. Only completed status is supported; other authentic statuses consume no notification action.

The notification action is derived from the session UUID preallocated before dispatch, with one immutable domain. It is distinct from the original, session, report, effect, capacity, DNC and contact actions. Changing a family, policy or verifier key cannot mint a new action. The existing permanent PostgreSQL exclusion is global to tenant and effect UUID, rather than partitioned by the selected owner. Claim-before-POST, uncertain acknowledgement and no replay remain unchanged. Notification bodies and authentication material are retained in the clinic-owned record only.

## Cold discovery and independent closure

Native account history requires separately current collection, decoded-record, original-record, verifier-key and source/restore grants. It includes archived and closed rows, bounds pages and selected/scanned records, checks full immutable original digests and rejects duplicate or half-matching runtime pairs. Two complete scans and protected original rereads must remain consistent. It needs neither a lost notification reference nor a local private call/session journal. The strict existing positive-report reader retains its separate codec and permission queries; both use a private bounded native HTTP/history primitive.

The runtime creates a separate notification-purpose provider reader from its actual captured account, credentials, from-number, deadline and fetch port. notifiedAt is an authenticated local receipt time, never a fabricated stoppedAt or endedAt. The read requires independently approved coverage of all creators, mutators, fallback/TwiML/transfer and restore sources. It checks canonical actual provider creation/start/end/update times, the exact physical SID/account/from/to/root identity, two equal completed-root observations and two complete empty child pages. Missing times, unsupported statuses, children, pagination, identity drift, permission loss or unavailable bodies keep closure unknown. The existing positive-speech reader keeps its original public shape and evidence domains.

## Separate ownership at the mutation

The recovery composition supplies the existing terminal-provider port and call-capacity owner. All native reads, including both discovery passes and the owner's final original reread, share the same physical API-user budget and one cumulative operation allowance. The whole operation is bounded; it does not restart a budget or deadline after discovery. Native verifier/source and provider grants remain current through the actual SQL release fence. Source-origin/restore approval and the current capacity owner are independent requirements.

There is no contact port in this composition. The native note and callback do not create a complete-no-stop report or settle contact/DNC. Missing or unclear speech, private input, absent notifications and lost unretained acknowledgements remain unknown. No new call, clinic mutation, charge, scheduler retry or default route is enabled.
