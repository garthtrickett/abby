## Product contract

- `voice.locale` and `voice.voiceId` are clinic-wide public preferences. Both default to `null` at version `0`. There is no inherited host default that overrides an unset preference for new voice admission.
- Locale is a canonical BCP-47 base name without extensions. Voice IDs are opaque host catalogue handles. A syntactically valid value is still unavailable unless the configured host declares a compatible pair.
- One clinic CAS version covers both preferences and all locations. Each successful edit records one targeted kind, previous/new value, actor and UTC time. Location policy, intake and notification versions remain independent.
- Partial configuration may be saved if the selected value has declared support. It supplies no executable speech profile. A complete pair must have current readiness evidence; incompatible or unready complete pairs reject without advancing preference history.
- A new call captures locale, voice, preference/host versions, transcription/synthesis/presentation versions, quality-evidence version and the pinned speech configuration hash. Ordinary edits and clears affect subsequent calls. An active call retains its captured profile.
- A host declaration is an assertion by trusted host code. Actual adapter construction must bind that exact profile before speech or transcription starts. A mismatched configuration, unsupported primary/fallback pair, unknown presentation version or stale quality evidence must deny admission through the existing truthful fallback path.
- Profile readiness does not grant automation, clinical permissions or a natural-language capability. Existing speech-quality and host capability gates remain authoritative. A preference edit cannot promote a failed evaluation configuration.
- Only public preferences/audit enter `clinic_voice_settings`. Provider credentials, prompts, transcripts, patient references and captured bindings are absent. Strict standalone patient storage remains phone-to-Cliniko-patient-ID links only; active profile state is transient there.
- Clearing remains possible after provider withdrawal. It does not require a provider lookup. Source portability freezes must also prohibit such a clear.

| `OpenAIVoiceProfileHost.resolve` / `create` | Clinic scope / captured profile and runtime | Catalogue and actual OpenAI adapters derived from the same versioned physical descriptor and scoped quality evidence |
| `closeUnattachedCall` | Admitted receipt or pending event, session owner, time and close reason | Owned terminal call/pending state without provider construction; ownership failures remain typed |

Registry lookup has a 1.5-second deadline and an abort signal. Throws, malformed/expanded replies, duplicate pairs, scope drift and invalid pinned metadata fail closed. Inputs and returned declaration values are cloned across the asynchronous lookup so later mutation cannot change the approved selection.

Memory and PostgreSQL stores implement the same contract. PostgreSQL uses a version-zero row as the clinic lock and rechecks both the version and the exact preferences used by pair preflight before appending. A same-version in-place counterpart change produces `storageFailure`, rather than committing a pair preflighted against different data.

Migration `040_clinic_voice_settings` stores scalar public values/audit, enforces version-zero and targeted-audit shapes, installs the existing portability write/truncate guards, and refuses rollback while nonzero history exists. Its Kysely row types are generated by actual Kanel/kanel-kysely, never handwritten.
