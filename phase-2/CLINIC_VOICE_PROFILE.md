## Status

In implementation on `codex/abby-clinic-voice-profile`. The core profile contract, public preference stores and migration have focused proof. They are not yet composed into `PolicyStore`, admin commands or the call runner. The runner still uses its previous server-level speech configuration. No setting-to-call or release claim is made here.

The full objective includes authenticated controls, actual captured adapter behavior, locale presentation, complete synthetic calls, carryover/cutover, scenario registration and parallel isolation. Production identity integration is a separate open D-14 task.

## Product contract

- `voice.locale` and `voice.voiceId` are clinic-wide public preferences. Both default to `null` at version `0`. There is no inherited host default that overrides an unset preference for new voice admission.
- Locale is a canonical BCP-47 base name without extensions. Voice IDs are opaque host catalogue handles. A syntactically valid value is still unavailable unless the configured host declares a compatible pair.
- One clinic CAS version covers both preferences and all locations. Each successful edit records one targeted kind, previous/new value, actor and UTC time. Location policy, intake and notification versions remain independent.
- Partial configuration may be saved if the selected value has declared support. It supplies no executable speech profile. A complete pair must have current readiness evidence; incompatible or unready complete pairs reject without advancing preference history.
- A new call captures locale, voice, preference/host versions, transcription/synthesis/presentation versions, quality-evidence version and the pinned speech configuration hash. Ordinary edits and clears affect subsequent calls. An active call retains its captured profile.
- A host declaration is an assertion by trusted host code. Actual adapter construction must bind that exact profile before speech or transcription starts. A mismatched configuration, unsupported primary/fallback pair, unknown presentation version or stale quality evidence must deny admission through the existing truthful fallback path.
- Profile readiness does not grant automation, clinical permissions or a natural-language capability. Existing speech-quality and host capability gates remain authoritative. A preference edit cannot promote a failed evaluation configuration.
- Only public preferences/audit enter `clinic_voice_settings`. Provider credentials, prompts, transcripts, patient references and captured bindings are absent. Strict standalone patient storage remains phone-to-Cliniko-patient-ID links only; active profile state is transient there.
- Clearing remains possible after provider withdrawal. It does not require a provider lookup. Source portability freezes must also prohibit such a clear.

## Current module interfaces

| Function or port | Input | Output / owner |
| --- | --- | --- |
| `ClinicVoiceSettingStore.read` | Exact tenant/clinic scope | Typed result containing raw preferences |
| `ClinicVoiceSettingStore.change` | Scope, expected clinic version, `locale` or `voiceId`, value/null, actor | CAS result and one public audit entry |
| `ClinicVoiceSettingStore.listChanges` | Scope and optional numeric cursor | Ordered public page, up to 50 entries |
| `VoiceProfileRegistry.resolve` | Scope and abort signal | Current scoped declaration of supported pairs and their pinned versions/readiness |
| `listVoiceOptions` | Registry and scope | Public labels and compatible pairs; no configuration hash or adapter/quality internals |
| `approveVoiceChange` | Registry, candidate preferences, targeted kind | Typed approval; incomplete setup grants no readiness |
| `captureVoiceProfile` | Registry, scope and complete preferences | Detached immutable-by-contract profile, or `readinessFailed` for `voiceProfile` |

Registry lookup has a 1.5-second deadline and an abort signal. Throws, malformed/expanded replies, duplicate pairs, scope drift and invalid pinned metadata fail closed. Inputs and returned declaration values are cloned across the asynchronous lookup so later mutation cannot change the approved selection.

Memory and PostgreSQL stores implement the same contract. PostgreSQL uses a version-zero row as the clinic lock and rechecks both the version and the exact preferences used by pair preflight before appending. A same-version in-place counterpart change produces `storageFailure`, rather than committing a pair preflighted against different data.

Migration `040_clinic_voice_settings` stores scalar public values/audit, enforces version-zero and targeted-audit shapes, installs the existing portability write/truncate guards, and refuses rollback while nonzero history exists. Its Kysely row types are generated by actual Kanel/kanel-kysely, never handwritten.

## Required composition and proof

1. **Policy and admission:** compose raw preferences and capture into both policy stores. Reject profile/binding fields injected through location policy or a default factory. New admission requires one coherent clinic profile across candidate locations before the greeting, even before location selection. Legacy text snapshots do not become new voice authority.
2. **Agent commands and authenticated UI:** register distinct locale/voice changes plus scoped catalogue/audit reads. Use the existing trusted actor gateway, clinic-admin role and Origin guards. Show raw versus effective state. Incompatible choices require an explicit clear/change sequence; the UI must not silently change the other setting. Lost or malformed save replies require rereading current scoped state without replay; a failed reread locks editing.
3. **Actual adapters and presentation:** bind transcription and synthesis per admitted call, including supported fallback adapters. Check their actual configuration against the captured hash and versions. Render caller-facing dates using the captured locale while preserving UTC/timezone arithmetic and exact clinical action identity. Advertise only locales supported by the compiled approved dialogue/presentation and configured adapters; adapter language support alone does not prove translated safety flows.
4. **Complete synthetic calls:** distinguish actual outgoing voices/adapter parameters and spoken locale presentation. Exercise each setting's default/set/change/clear, unsupported pair, stale quality/version/scope, role/Origin, old versus new calls, reply loss and a mid-resolution clinic-version change. Unset/partial/mismatched profiles must fail before transcription or patient reads/writes. No raw setting can authorize a clinical operation.
5. **Carryover and cutover:** export one public history per clinic, preserve source events, and append independent audited target clears in locale-then-voice order. Import no executable binding or provider/quality authority. Reject occupied targets, unlisted source clinics, altered history and source writes after freeze. Reconcile the exact imported target state before number publication; no minimal standalone publication claim is implied by an embedded synthetic proof.
6. **Scenario and release evidence:** allocate `E2E-258` / `E2E-259` for the two settings and register them only with truthful evidence status. Run full local regression, actual generation without drift, each mapped file alone and all mapped files in both parallel orders, with existing four Node/three browser workers and zero mapped skips. Real carrier and real provider quality remain separate gates.
