Status: local engineering qualification passed, 20 October 2026; new-head cloud qualification pending. No default activation or live clinic/carrier acceptance. This continues [the execution order](EXECUTION_ORDER.md) and the [positive speech producer](TWILIO_OUTBOUND_STOP_SPEECH.md).

## Delivered contract under qualification

A clinic-selected Twilio/Abby finality adapter can recover an authenticated positive stop from native Cliniko records after loss of volatile session context. It requires fresh independent provider evidence that the complete, explicitly approved single-root call has ended. It then supplies final STOP to the existing native contact-settlement owner and terminal truth to the separate call-capacity owner.

The original early report stays immutable. Its reserved report action is not reused for a later final report. The existing original `contactReferences.outcomeActionRef` owns final native contact retention. Call and contact holds retain separate owners and release grants; releasing one does not release the other. Original effect, session, report, DNC and outcome exclusions stay consumed. No new private call index or patient-bearing SQL journal is introduced.

This positive-only adapter never returns complete no-stop. Unknown ASR, silence, missing reports or socket closure cannot prove that nobody opted out. The real OpenAI adapter still emits uncertain quality. Exact uncertain stop wording closes conservatively without a positive report/DNC and keeps its holds. Synthetic clear-quality witnesses do not qualify real acoustics. The independently verified original-patient/exact clinical handoff and gap13 remain separate.

## Source and permission boundaries

1. `ClinikoTwilioOutboundRuntimeHistory` accepts only the original opaque runtime effect/capacity pair and a fixed selected account. It requests a separately approved account-wide native body, with closed/archived rows included and the unchanged500 scanned/50 selected/five-page bounds. There is no invented native phone/type search filter.
2. Every selected report needs an independently permitted exact reread and verification by the selected MAC key. Every claimed original possible-attempt record needs its own protected decoded read. The whole canonical original digest must equal the immutable authenticated report assertion. Current editable notes alone cannot supply original SEND authority. Duplicate actions/origins, half-pair matches, altered records, changed/incomplete scans, wrong key/account, permission loss and bad clocks refuse. A full rescan and exact original rereads precede disclosure. Lost session/report IDs are not fabricated to invoke the old reader.
3. `TwilioAbbyOutboundRuntime.createCallClosureReader()` captures the actual launch owner's account, credential, source number, runtime binding, deadline and transport. The finality consumer cannot silently choose a different provider account/token. Provider requests are fixed authenticated HTTPS GETs with no redirect or retry and owned bounded response bodies.
4. A separate current `approveExclusiveSingleRootProfile` grant covers **all call creation, mutation, fallback/TwiML/transfer and restore sources**, bound to the exact original native evidence and selected runtime. Its coverage cannot be inferred from the local source file, an ended root or an empty list. Without this independently reviewed complete-source condition, finality remains unknown. The fixed profile is one original POST with Connect/Stream/Hangup; any unexpected child call, pagination, malformed/missing history or unsupported profile remains unknown.
5. Two exact root reads and two complete empty `ParentCallSid` child pages must agree. The root must match account, SID, source/recipient, outbound direction, parent and resource URI. A positive answered-speech observation requires a completed root with real bounded provider creation/start/end/update times; busy/failed/unanswered or missing end time cannot supply an invented timestamp. Later billing-only update metadata does not change the stable final contact identity.
6. All strongest native and provider grants remain current across waits. Native evidence is rediscovered and compared again after provider inspection. A stable composite digest binds the immutable positive report and provider closure. The report's positive stop dominates unknown speech tails for STOP only; it does not establish negative speech coverage or patient identity.

The [Twilio Call resource](https://www.twilio.com/docs/voice/api/call-resource) documents the UTC RFC2822 lifecycle times, parent-call filtering and list pagination. The implementation conservatively declines unsupported/missing completion fields. The delayed Call Event resource is not used as an immediate completeness oracle. These API observations are distinct from clinic source/restore acceptance.

## Existing independent owners

`recoverTwilioOutboundFinality` composes the concrete adapter with `ClinikoOutboundContactSettlement` and `ClinikoOutboundTerminalOwner` inside one bounded purpose. All native scans, exact reads and writes use one captured physical API-user budget and a shared180-claim operation bound, including across a real minute rollover. No fresh owner resets that allowance. Each owner's original source, patient-record, policy, producer/restore, DNC, outcome and release permissions remain necessary.

Native final outcome retention precedes global contact-hold release. A stored lost acknowledgement is discovered through independently authorized native history; an unobserved consumed write is not replayed. The separate terminal owner checks original campaign/capacity scope and current release permission before its real SQL release. A known result from one owner survives an unavailable result from the other. Recovering or ending a contact grants no clinical action.

No callback, background consumer, scheduler, server default, deployment or live provider invocation is activated here. Hosts must explicitly select the adapter at the existing replaceable runtime seam and provision every independent source and purpose grant. A future hosted conversation runtime can implement the same generic runtime interface without entering the native clinic owners through provider-specific branches.
