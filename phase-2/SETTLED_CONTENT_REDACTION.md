# Settled voice content in the call ledger

The call transition retains approved speech and notice text while a presentation is pending or started, because the dispatcher still needs the exact committed wording. When the presentation becomes played, interrupted, failed, unproven, or superseded, the same transition replaces its `approvedText` with an empty string. The presentation ID, status, action key, and digest remain available for confirmation and recovery. Ending a call also clears its `callerMessages` buffer. Later effect results cannot repopulate that buffer on an ended call.

The synthetic voice journeys check that pending text reaches playback, settled presentation text is removed, ended call messages are absent from memory and PostgreSQL call state, and a played action can still be confirmed. This covers the current logical ledger row. It does not erase prior database backups or WAL, migrate older calls that receive no further transition, or implement the host's consent and retention policy. Active calls still retain `callerMessages`, and action/effect payloads retain the references needed for reconciliation. Those require a separate retention policy and deletion path before live clinical use.
