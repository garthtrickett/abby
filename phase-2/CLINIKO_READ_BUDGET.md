# Cliniko read budget

Cliniko [limits API requests to 200 per minute per user](https://docs.api.cliniko.com/#rate-limits) and returns HTTP 429 with a UNIX-seconds `X-RateLimit-Reset`. `ClinikoReadBudget` reserves a request before any of the patient-candidate, available-time, or appointment-read adapters calls HTTP. Pass **one instance for the same Cliniko API user** through each adapter's `rateBudget` configuration. It caps Abby's requests in a rolling minute and, after any 429, makes the other readers return a typed `rateLimited` outcome without sending another request until the reset. An absent or invalid reset header causes a one-minute local cooldown. Requests are not automatically retried: the caller's turn or proof may be stale by the time a retry would run.

The budget lives in one Node process. A deployment with more than one process or other integrations using the same Cliniko user needs a shared host-level budget; this class alone does not guarantee the account-wide limit. It stores only request times and the reset instant, not the API key or response body. `test/cliniko/shared-read-budget.test.ts` sends a synthetic 429 through the patient reader, checks that availability and appointment readers send no HTTP during cooldown, then checks both resume at reset. It also checks local exhaustion, concurrent callers, and an invalid reset header. No demo-account write or live caller is involved.
