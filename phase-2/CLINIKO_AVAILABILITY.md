# Cliniko read-only availability adapter, version 0.1

`ClinikoAvailabilityReader` binds a Cliniko API key, location scope, business, practitioner, and appointment type at construction. It derives the shard from the key suffix and sends authenticated HTTPS `GET` requests with Abby's contact User-Agent. It never sends a mutation request. A cross-scope call or invalid date range is rejected before HTTP.

For an availability request, the adapter reads the business, practitioner, and appointment-type online-booking flags. A `false` flag returns `notEligible` without querying times; an unknown flag or malformed record fails closed. The business must supply a valid IANA `time_zone_identifier`; it is carried with the result for local date validation and caller wording. The adapter then reads all bounded available-time pages, checking count consistency and each timestamp, and records when the read completed. Results are explicitly `reservable: false`: a displayed time is neither a hold nor `BookableOffer` evidence for a host write. Rate limits, permission failure, missing resources, provider outage, and malformed data remain distinct typed outcomes. Redirects are disabled, and response bodies and pagination are bounded.

The provider contract suite uses a fake HTTP transport and runs in parallel with the text and PostgreSQL suites. It covers shard/auth headers, multi-page reads, each online-booking flag, cross-tenant rejection, invalid ranges, typed provider faults, oversized responses, and inconsistent pages. Run `npm test` and `npm run probe:postgres`.

For a composition that also uses patient or appointment reads under the same Cliniko user, pass a shared [read budget](CLINIKO_READ_BUDGET.md) to every adapter.

The adapter now runs through an [opt-in synthetic call path](CLINIKO_CALL_READ.md) with final-turn, playback, failure, and daylight-saving tests. [C-LIVE-05](../phase-0/CLINIKO_EVIDENCE.md) re-probed the actual TypeScript adapter against the demo account for both appointment types and verified restoration of the business's online-booking flag. The business time zone is currently `Asia/Jakarta`; caller wording must reflect that setting. The adapter has not been invoked through live media. It does not verify a patient, issue a stable offer, reserve a slot, or implement Cliniko writes. Cliniko booking therefore remains request-only in the draft support matrix. Before live caller-facing availability is enabled, the product still needs approved time-zone wording, a route and permission mapping, and a real media call that proves the spoken result and fallback.

The request shape and online-booking behavior follow Cliniko's [API introduction](https://docs.api.cliniko.com/), [sharding guide](https://docs.api.cliniko.com/guides/sharding), [Available Time reference](https://docs.api.cliniko.com/openapi/available-time), and [Business time-zone field](https://docs.api.cliniko.com/openapi/business).
