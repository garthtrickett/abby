# Model-assisted text turn

`calls.turn.model.v1` is an opt-in agent command for a call whose captured automation policy is enabled. It accepts a final text turn, not a model proposal. The gateway checks actor scope and the command schema. The call transition records the turn and an opaque model effect together, clears older pending speech, and never persists the caller's words in that effect or its audit event.

`ModelWork` holds at most 1,000 raw turns in process memory for at most 60 seconds and bounds each turn to 4,000 characters. The effect worker calls a host-supplied `RawModelPort` through the typed ingress, then submits the result through the same versioned SAM transition as other effects. Missing transient input after a process loss resolves to a typed unavailable result and staff follow-up. A full transient queue or overlong turn accepts the turn directly as staff fallback, including an idempotent replay, without calling the model. A newer turn, speech onset, or call end cancels stale pending model and knowledge effects; late results cannot restore old speech. The host model adapter must honor the abort signal and its provider retention policy; deleting Abby's local task does not revoke data already sent to that provider. The model port and prompt version are injected by the embedding host. The reference demo supplies neither, and these tests use a fake port with no LLM credentials.

When the host supplies `listModelKnowledge`, the reception reads current approved sources for the captured location before accepting a model turn. It validates scope, approval, effective time, unique references, and a limit of eight sources with 2,000 characters per text. A failed or invalid list accepts the turn as staff fallback before inference. Only source references and approved text enter the transient model input; the durable effect contains neither. Hosts without this optional read provide an empty model context. The reference host lists valid current sources. A source changed or revoked after the snapshot still fails the separate fresh host read before speech. The model context is a bounded candidate set, not authority to answer or write.

An answer proposal creates a second durable host-knowledge read intent. Its source references and unapproved text remain transient; the intent stores only a source-reference digest. The worker retrieves the source from the host, and the acceptor permits speech only when one current, approved, correctly scoped source exactly matches the proposed text. Invented wording, missing sources, malformed model output, timeouts, and lost transient input produce a truthful generic notice and staff work. Lookup and action proposals currently request staff follow-up. They cannot produce a patient proof, confirmation token, or host write.

The E2E text journeys cover default-off and unconfigured behavior, tenant isolation, a verified answer, an action proposal, invented wording, unapproved source references, a lost worker wake-up, malformed output, lost transient input, duplicate turns, and a caller correction while model work is in flight. PostgreSQL also rejects a malformed persisted model intent before recovery. The journeys run on the memory and PostgreSQL ledgers. [Synthetic voice journeys](MODEL_VOICE_TURN.md) now submit final turns through this path. No live model quality or media latency has been evaluated. [Settled content redaction](SETTLED_CONTENT_REDACTION.md) clears completed presentation text and ended call messages; full consent and retention controls remain necessary before a real caller pilot.
