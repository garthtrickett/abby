# Emergency stop for appointment writes

`calls.writes.stop.v1` is a clinic-admin command bound to the actor's tenant and clinic. It records the operator, reason, version, and database time. A repeated stop while already stopped returns the current receipt. `calls.writes.stop.read.v1` returns the persisted status and pages through a snapshot of host writes that were `possiblySent` or `uncertain` when the current stop took effect. Those writes may already have reached the host, so their receipts and reconciliation continue. The stop is clinic-wide across locations and does not change the captured call policy or the new-call automation switch.

If an in-flight outbox row has lost its action key, the stop still latches and the snapshot labels that key `unknown`; corrupt audit metadata cannot leave dispatch open.

The memory and PostgreSQL ledgers enforce the stop in the same atomic step that would mark a pending host write `possiblySent`. PostgreSQL locks a clinic barrier row for the send mark and the operator stop, so one operation wins before the other. If the stop wins, the host adapter receives no send permit: the effect is canceled, the action becomes unsupported, and a linked staff request is staged. The call records a truthful caller message and stages it for speech when its presentation slot is free. Staff tasks and reconciliation are not blocked. The reference dashboard exposes the stop and its in-flight snapshot; the browser and both ledgers exercise a pending write through this path.

`calls.writes.resume.v1` requires the current stop version, an operator reason, and fresh host-owned readiness evidence. Its default readiness gate refuses recovery. If readiness passes, the same clinic row lock records a new version with `stopped: false`; a stale version fails without reopening dispatch. A later incident can stop again at the next version. `calls.writes.stop.audit.v1` pages through every stop and resume decision, while each stop retains its own in-flight snapshot. The forward migration from the original stop schema preserves the first stop as version 1 and keeps its snapshot.

Recovery reopens only the dispatch barrier. A deploying host must still enforce current permission and capability at its mutation boundary; a successful readiness check does not grant a write on its own. This slice has no live telephony or Cliniko write adapter; synthetic tests cannot establish provider behavior. A production host must authorize the clinic-admin identity, start the effect worker, and monitor staff follow-up.
