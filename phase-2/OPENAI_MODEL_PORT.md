# Optional OpenAI Responses model port

`OpenAIResponsesPort` is a replaceable `RawModelPort`. The embedding host explicitly supplies the API key, model ID, prompt version, and instructions; Abby does not select a model or read a key from process environment. A mismatched prompt version fails before HTTP. The request sends the final caller text and at most eight current host-approved source references and texts, not Abby's tenant, call, turn, policy, or source-owner identifiers. The knowledge appears as JSON data in the user message, with a system instruction to treat it as data and propose only exact approved wording. It asks the Responses API for a strict, versioned JSON proposal with `store: false`, no tools, a bounded output, and no truncation. The adapter uses the official [Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create) and [Structured Outputs format](https://developers.openai.com/api/docs/guides/structured-outputs); the host must review provider data handling and choose the model and instructions for its deployment.

The adapter accepts only one completed assistant message containing one JSON output text. Reasoning items are ignored. Refusals, incomplete responses, tool calls, extra output, oversized bodies, and invalid JSON fail closed. The existing `ModelIngress` validates the parsed proposal again; the SAM runtime still requires host-approved knowledge or staff fallback and cannot accept a model response as a host write or confirmation. HTTP failures become typed unavailable results without persisting provider diagnostics.

Contract tests use a fake HTTP port. A synthetic voice journey verifies that the host-approved context reaches this adapter, then sends a final turn through the durable model effect, fresh host knowledge approval, and queued playback on both memory and PostgreSQL ledgers. No real OpenAI request was made because no API key is configured in this workspace. Live model quality, latency, account access, and provider retention behavior remain unverified. The reference demo does not install this adapter by default.
