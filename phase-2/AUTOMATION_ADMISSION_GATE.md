# Default-off automation admission gate

`CallPolicy.automationEnabled` defaults to `false`. `CallAdmissionService` looks up an authenticated provider call key before reading the current route or switch. A matching existing receipt is acknowledged as a duplicate even if automation has since been disabled; a conflicting dialed number still fails. For a new key, a policy without `automationEnabled: true` produces typed `automationDisabled` and writes no call receipt. `AdmissionFallbackCoordinator` sends that outcome to the independently configured number fallback and operational alert. An already admitted call retains its captured policy and may finish.

The PostgreSQL policy reader treats older setting versions without this field as disabled. Memory and PostgreSQL synthetic E2E cover the default, enabled route, disabled new call, existing-call continuation, duplicate replay, and fallback. Tests explicitly mark their synthetic routes enabled; the reference default and standalone dashboard demo remain off.

The clinic-wide `settings.automation.enabled.change.v1` admin command changes this switch through a separate version stream from the location-level booking setting. Enabling requires a host-owned readiness result covering permissions, selected location, approved knowledge, bookable offers, staff and after-hours destinations, notification ownership, fallback route, and a passed media test call. The default readiness implementation rejects enabling; synthetic tests inject explicit success. A fresh call checks readiness again so a lapsed prerequisite blocks new admission. Duplicate provider-call replay is resolved first. Disabling does not interrupt an admitted call. Each change records the actor, previous and new value, version, and time in a clinic-scoped audit stream. The lit-html dashboard exposes the command and history to clinic admins, and browser-plus-call and PostgreSQL journeys cover the setting.

This implements the setting contract and fail-closed boundary, not real readiness evidence. A deploying host must supply and maintain trustworthy evidence for each prerequisite. The media call, provider-number fallback, and live interruption and playback behavior still need real end-to-end tests before a clinic can enable automation.
