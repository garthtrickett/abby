# Pre-location session lease

A shared-number call now reserves its provider call key before media attaches. `attachPendingLocationSession` issues one durable 30-second lease for a named session, capped by the two-minute location-choice deadline. A replay from that session returns only the remaining duration; a different session cannot attach. `renewPendingLocationSession` fences renewals by lease version, accepts an immediate replay of the previous version without extending time, and never extends past the choice deadline. PostgreSQL makes these decisions with its database clock and the call-key transaction lock.

`SharedNumberIntakeService.choose` now requires a clear final caller turn with the correct call ID, session ID, and turn ID. It rejects a missing, foreign, or stale lease before reading selected-location policy. `bindPendingLocation` checks the same session and lease version inside its atomic transaction, then records the selected location and final turn reference as choice evidence. A bound replay must match that evidence. Lease expiry is included in the independent liveness scan, so an abandoned media session closes the pending choice before its two-minute outer deadline.

The bound call receives a fresh location-scoped admission deadline and then its normal voice-session lease. The pre-location session can no longer renew after binding. The transport adapter still needs to present candidate locations, connect playback and final transcript evidence to this lease, and hand media over to the bound call session. This contract alone does not prove a live caller-facing prompt.
