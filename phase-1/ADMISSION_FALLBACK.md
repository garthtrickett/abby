# Synthetic admission fallback, version 0.1

`AdmissionFallbackCoordinator` runs after an authenticated inbound event has been decoded. It first asks `CallAdmissionService` for the globally keyed receipt. A created or duplicate receipt returns to the caller unchanged; a conflicting replay or malformed event is rejected and never starts a second route. `routeUnavailable`, `unknownNumber`, `ambiguousClinic`, `locationChoiceRequired`, `automationDisabled`, `readinessFailed`, `storageFailure`, or `storageCorrupt` without a proven receipt asks an independently configured provider fallback port to handle the authenticated account and dialed number. Other error kinds do not implicitly gain fallback behavior. The request carries a stable call ID so the provider adapter can make retries replay-safe. The coordinator never reads clinic policy to select that route.

The fallback port returns `connected` with a nonempty opaque provider connection reference only for provider-proven connection, `failed` for proven failure, `notConfigured` for no route, or `unproven` when the outcome is unknown. A thrown or malformed provider result becomes `unproven`. A separate operational alert is attempted with the call ID, admission failure kind, and fallback outcome; alert failure is reported without changing the provider outcome. This result does not create an Abby call receipt or authorize a host action.

Memory and disposable PostgreSQL tests cover created and duplicate calls, changed-number conflict, malformed events, route failure, absent fallback, malformed or thrown provider results, and independent alerting. A memory test forces ledger failure before policy resolution. Run `npm test` and `npm run probe:postgres`.

This is a synthetic coordinator contract. The provider adapter must still prove authentication, an account-and-number scoped fallback configured outside Abby, idempotent handling of the call ID, a bounded alert attempt, and what counts as connected. Activation failure after a durable receipt, process loss, and live number-routing failover need separate transport tests. No fallback result here is live telephony evidence.
