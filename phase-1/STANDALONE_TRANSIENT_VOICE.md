# Standalone transient voice composition

`createStandaloneTransientVoiceCall` is a synthetic integration seam for a signed Twilio stream. It checks the standalone PostgreSQL privacy preflight before constructing a call. PostgreSQL supplies only minimal clinic policy and automation settings. The authenticated call then owns one `MemoryLedger`, one SAM runtime, and one voice session. The standalone host disables patient mutations and staff tasks. The call wrapper disconnects the transport, clears the ledger, and releases its call reference on stop, failure, or socket closure.

`E2E-134` authenticates a synthetic Twilio webhook and stream, exercises greeting playback and a final caller turn through this composition, reads provisional availability through the Cliniko adapter, and checks the safe answer sent to synthesis. It then proves the voice tables are empty and scans the disposable database and data-only backup for caller phone, provider call ID, transcript, appointment ID, and appointment-time canaries. Rich legacy settings block construction before any media is sent. This is a storage-boundary proof, not a production voice readiness result. The test injects synthetic readiness, transcription, synthesis, routing, intent resolution, and Cliniko HTTP responses; no real number or live provider call is involved.

`E2E-137` adds a transient OpenAI Responses intent adapter to the synthetic call. It sends only caller text and the clinic-local date, requests a structured decision with `store: false` and no tools, and accepts only a valid seven-day availability range or an unsupported request. Unsupported requests use the existing generic fallback. Malformed, unsafe, or unavailable model output yields `intentUnavailable`; no patient-specific action is selected. The integration still uses a fake model HTTP response and does not establish live model accuracy or provider data-retention terms.

`createStandaloneClinikoVoiceServer` now wires the signed HTTP/WebSocket ingress to per-call Realtime transcription, speech synthesis, the typed availability intent resolver, and a route-specific Cliniko availability reader. Route and fallback numbers must match, and each call creates its transcription session only after the database privacy preflight. `E2E-138` enters this server through a signed local webhook and WebSocket and proves greeting media is queued without storing caller data. `E2E-139` proves that the first Realtime `needsClarification` turn receives a generic spoken repeat prompt, while a second uncertain turn closes the stream to the configured post-stream fallback. Neither uncertain turn queries the model or Cliniko or creates a patient task; the disposable database and backup canary scan remain clean. These are integration proofs with fake provider responses, not live call evidence. Because the chosen transcription model has no confidence score, the server currently cannot answer a spoken availability question; a separately evaluated quality policy is required before promoting transcripts to `clear`.

`E2E-140` adds the clinic-approved keypad path on the standalone Cliniko server. Every configured route must supply a clinic-approved greeting that says to press 1 for today's possible times and press 2 for tomorrow's. A signed, validated inbound key after that greeting is played bypasses transcription and model inference and reads only the chosen clinic-local date from Cliniko. Keys during active audio or playback, and unsupported keys, do not trigger a read. The same transient SAM presentation and playback acknowledgment speak the provisional answer; the local signed-socket test scans PostgreSQL and a disposable backup for patient-specific canaries. This path has no live Twilio evidence and does not change the patient-call launch gate.

The transient Twilio call renews its process-local lease every ten seconds while connected and closes the socket on terminal lease loss. The volatile ledger resolves the immediate conflict between a rich live SAM state and Abby's ban on durable patient-linked outcomes. The HTTP ingress rejects duplicate streams within one server process, including a fresh signed webhook for a call it already claimed during the original three-minute claim window. The standalone server additionally requires a PostgreSQL session advisory lock for each active provider account and call ID. It proves at startup that the lock adapter and policy database share a lock space. A second server cannot own the same active call, and loss of the lock session closes its socket; `E2E-170` verifies both through two signed local servers. The lock key is HMAC-derived and exists only in PostgreSQL's transient lock state, not an Abby table or backup. The signed webhook also carries an independent static post-stream staff dial, but no live fallback connection is proven.

Active ownership is **not** a durable replay receipt. After a process dies and its lock releases, another signed stream could be admitted for the same provider call ID. A process loss also discards the volatile SAM state. D-12 makes durable admission, later replay, and the independent lease monitor embedded-host requirements, not standalone Cliniko promises. Standalone patient calls remain disabled until a real telephony fallback test and the other clinic readiness gates pass. The reference PostgreSQL voice ledger remains explicitly unsafe for such traffic.
