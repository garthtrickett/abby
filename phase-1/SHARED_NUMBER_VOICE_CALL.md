# Shared-number voice call handoff

`SharedNumberVoiceCall` is the synthetic transport-facing coordinator for one authenticated inbound call and one session ID. `begin` uses `SharedNumberIntakeService`: a single-location number immediately attaches the ordinary `VoiceSession`, while a shared number attaches `PrelocationVoiceSession` and sends its captured location prompt. No location-scoped session is constructed before a choice commits.

The coordinator routes playback results, speech starts, and transcript segments to the active session. A clear location turn durably binds the selected location before the coordinator constructs and attaches the ordinary voice session with the same call ID, session ID, and playback port. It checks that the host-supplied full session matches the bound scope. If constructing or attaching that session fails, the bound receipt remains durable and `resumeBound` can retry attachment without a second location decision. Late location-prompt callbacks cannot become ordinary call playback evidence.

`end` waits for an in-flight choice transition before deciding which session to close. Before a choice, it fences and expires the pending reservation immediately; after binding, it ends the location-scoped call. The ledger records the disconnected session and marks any possibly sent prompt unproven unless a successful clear proved interruption. A duplicate close returns the same terminal state. A bound admission whose full-session attach failed remains `starting` until its independent admission monitor closes it; the coordinator reports `sessionUnavailable` for that gap.

Memory and PostgreSQL journeys enter through this coordinator. They prove prompt delivery, location choice, scoped booking details, played confirmation, and a committed host booking only in the chosen location; they also cover the single-location path, wrong-scope factory retry, disconnect during choice, and a disconnect racing binding. A [synthetic media controller](MEDIA_TURN_CONTROLLER.md) drives location, booking, and affirmation turns from normalized PCM frames. A [streamed playback port](STREAMED_PLAYBACK_PORT.md) proves chunked output and exact completion before affirmation. The [connected call owner](CONNECTED_VOICE_CALL.md) now composes both paths and owns turn-driven dispatch and cleanup. Optional [OpenAI speech](OPENAI_SPEECH_SYNTHESIS.md), [transcription](OPENAI_REALTIME_TRANSCRIPTION.md), and [Twilio protocol with signed local ingress](TWILIO_MEDIA_STREAM.md) adapters have synthetic tests; a live signed provider call, live media, transfer, fallback, and privacy-safe standalone voice storage remain open. This is a no-number proof of the handoff, not a live `E2E-055` result.
