# OpenAI Realtime transcription adapter, synthetic proof

`OpenAIRealtimeTranscription` implements Abby's `TranscriptionPort` for one live call. It connects to OpenAI's [Realtime transcription session](https://developers.openai.com/api/docs/guides/realtime-transcription) with transcription intent, selects `gpt-live-transcribe`, and configures mono PCM16 at 24 kHz with server turn detection disabled. Abby converts its 16 kHz media frames to 24 kHz in memory and sends each as an `input_audio_buffer.append` event. Abby's own `MediaTurnController` decides speech onset and silence; only then does the adapter send `input_audio_buffer.commit`.

The adapter waits for `input_audio_buffer.committed` and matches the final `conversation.item.input_audio_transcription.completed` by `item_id`. Foreign completions, including those from an older turn, cannot become a caller turn. Empty text produces no final speech. OpenAI does not return a confidence score for this model, so the adapter marks final text `needsClarification`; it never treats a transcript alone as clear evidence for an action or confirmation. It validates the resolved session configuration and bounds outgoing socket data and incoming events. Failed configuration, provider errors, malformed events, lost connection, cancellation, or the controller's deadline return `transcriptionUnavailable` and close the socket. The adapter keeps audio and transcripts in process memory only; it writes no patient-specific data to Abby storage.

The synthetic `E2E-129` test drives the real media controller and turn assembler through a fake Realtime socket, verifies 16 kHz to 24 kHz conversion and commit timing, and exercises mismatched completions and failures. A stopped call closes the connection. The server process must supply the API key; it must not be exposed to the browser or persisted in a call record. `createStandaloneClinikoVoiceServer` now composes this adapter with signed Twilio ingress and transient storage; no deployed phone transport has been proven.

This is a protocol-level synthetic proof. No OpenAI key is configured in this workspace, so the actual Realtime handshake, provider transcription quality, latency, and noisy-caller behaviour remain unverified. A separate quality gate must be designed and evaluated before any transcript can be considered `clear` for automated actions. The current standalone voice composition uses a per-call memory ledger and passes a database and backup canary scan, but has no durable crash recovery. The adapter does not satisfy the Phase 1 live-call gate or permit patient calls by itself.
