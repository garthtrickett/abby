# OpenAI Realtime transcription adapter, synthetic proof

`OpenAIRealtimeTranscription` implements Abby's `TranscriptionPort` for one live call. It connects to OpenAI's [Realtime transcription session](https://developers.openai.com/api/docs/guides/realtime-transcription) with transcription intent, selects `gpt-live-transcribe`, and configures mono PCM16 at 24 kHz with server turn detection disabled. Abby converts its 16 kHz media frames to 24 kHz in memory and sends each as an `input_audio_buffer.append` event. Abby's own `MediaTurnController` decides speech onset and silence; only then does the adapter send `input_audio_buffer.commit`.

The adapter waits for `input_audio_buffer.committed` and matches the final `conversation.item.input_audio_transcription.completed` by `item_id`. Foreign completions, including those from an older turn, cannot become a caller turn. Empty text produces no final speech. OpenAI does not return a confidence score for this model, so the adapter marks final text `needsClarification`; it never treats a transcript alone as clear evidence for an action or confirmation. The voice session now speaks one generic repeat prompt for an uncertain turn and refuses a second uncertain turn so the signed stream can use its static fallback. It validates the resolved session configuration and bounds outgoing socket data and incoming events. Failed configuration, provider errors, malformed events, lost connection, cancellation, or the controller's deadline return `transcriptionUnavailable` and close the socket. The adapter keeps audio and transcripts in process memory only; it writes no patient-specific data to Abby storage.

`E2E-146` adds a defensive event-order case: if a final arrives before the commit acknowledgment, the adapter holds at most eight candidate finals in memory and releases only the one whose `item_id` matches the acknowledged commit. Duplicate or excessive early finals close transcription. The [official OpenAI Realtime transcription guide](https://developers.openai.com/api/docs/guides/realtime-transcription) requires matching events by `item_id` and confirms that `gpt-live-transcribe` supplies no confidence score. This does not promote the matched text to `clear` or prove live-provider event timing.

The synthetic `E2E-129` test drives the real media controller and turn assembler through a fake Realtime socket, verifies 16 kHz to 24 kHz conversion and commit timing, and exercises mismatched completions and failures. A stopped call closes the connection. The server process must supply the API key; it must not be exposed to the browser or persisted in a call record. `createStandaloneClinikoVoiceServer` now composes this adapter with signed Twilio ingress and transient storage; no deployed phone transport has been proven.

The [live synthetic-audio evaluation](../eval/LIVE_BASELINE_2026-09-29.md) now exercises the actual Realtime handshake and adapter with both clean and G.711 telephone-band patient-free fixtures; each corpus matched 9 of 9 repeated transcripts. That clean synthetic speaker and local frame pacing cannot establish noisy-caller, accent, real telephony, or pilot performance. A separate quality gate must be designed and evaluated before any transcript can be considered `clear` for automated actions. Until then, the standalone speech route gives one generic clarification and cannot use this adapter's final text for natural-language availability or patient actions; an approved keypad availability route remains separate. The current standalone voice composition uses a per-call memory ledger and passes a database and backup canary scan, but has no durable crash recovery. The adapter does not satisfy the Phase 1 live-call gate or permit patient calls by itself.

The [opt-in signed local live test](../eval/README.md#signed-local-live-speech-evaluation) now sends patient-free G.711 caller media through the signed standalone WebSocket and actual Realtime adapter. Its final produces the approved clarification and a second local completion mark, with zero intent-model requests and zero Cliniko reads at that point. A later clinic-approved keypad choice triggers a read-only fake Cliniko availability response and a third local mark. This is a direct composition check of the conservative quality gate and keypad recovery, not evidence that the spoken request was understood well enough to authorize a read or action.

The [two-speaker synthetic noise stress run](../eval/LIVE_BASELINE_2026-09-29.md#noisy-two-speaker-transcription-stress) exposed missed date, booking, and urgent-language terms in the real adapter despite clean and telephone-band fixtures matching earlier. Its deterministic white noise is not real caller evidence, but it reinforces the existing rule: no Realtime final from this adapter is promoted to `clear` or used for a Cliniko read or patient action.

The adapter now accepts an explicit `gpt-transcribe` model for a bounded committed-turn evaluation while `gpt-live-transcribe` remains the production default. `E2E-162` proves the candidate's configured model is checked, only the committed item can yield a final, and detected-language metadata cannot promote its text above `needsClarification`. The [real Realtime comparison](../eval/LIVE_BASELINE_2026-09-29.md#realtime-committed-turn-transcription-comparison) improved the noisy synthetic result but still missed safety terms. No standalone route selects the candidate or changes its caller-action gate.
