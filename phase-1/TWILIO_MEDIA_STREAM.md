# Twilio bidirectional media protocol, synthetic proof

`TwilioMediaStream` handles one already authenticated Twilio `<Connect><Stream>` WebSocket. It requires the expected account SID and call SID from a validated inbound webhook and signed WebSocket upgrade. It rejects mismatched start identities, stream SIDs, gaps in Twilio event or media chunk order, malformed base64, unsupported media format, and oversized frames. Incoming 8 kHz μ-law is converted to Abby's 16 kHz PCM media frames without storing the audio.

The adapter implements Abby's `AudioOutputPort`. It converts 16 kHz PCM to Twilio's 8 kHz μ-law and sends only Twilio's documented `media`, `mark`, and `clear` messages. `queueChunk` and `finishQueue` mean the socket accepted data for sending, not that the caller heard it. Only an exact returned `mark.name` for the completed output becomes `played` evidence. Twilio also echoes marks when it clears buffered audio, so marks from a canceled output are ignored. `clear` sends a new fence mark followed by `clear` and waits for that mark's echo before claiming queued audio cannot play later; a lost echo returns false and closes the protocol state. This follows [Twilio's Media Streams message contract](https://www.twilio.com/docs/voice/media-streams/websocket-messages).

`TwilioConnectedCall` serializes the protocol events through Abby's `ConnectedVoiceCall`. A successful start begins admission and queues only the committed greeting; media enters Abby's turn controller, and an exact completion mark settles playback. The synthetic `E2E-130` tests drive that reference-host journey plus codec conversion, clear echo, identity mismatch, malformed input, and missing clear evidence. These are local protocol tests, not a live Twilio call.

`TwilioSignedIngress` validates the inbound form webhook and WebSocket upgrade with Twilio's Node SDK against configured public URLs. It issues `<Connect><Stream>` with a short-lived HMAC binding in a custom parameter, then checks that binding against the signed stream's start account and call SID before returning an `AuthenticatedInboundCall`. This is transient call context; it is not stored in Abby's database. `createTwilioIngressServer` provides the Node HTTP/WebSocket transport: it refuses unsigned upgrades, buffers only `connected` and `start`, creates a call owner after authentication, and passes subsequent messages in wire order. It closes the socket on protocol failure or a missing start. `E2E-131` covers the synthetic signed chain, a local HTTP/WebSocket exchange, and forged, changed, and expired inputs. The binding key and Twilio auth token must be provided as runtime secrets shared across serving instances.

`E2E-132` sends that signed local exchange into `TwilioConnectedCall` with the reference memory ledger. It observes greeting `media` and `mark` on the WebSocket, echoes the exact mark, verifies the ledger records `played`, sends caller media through a final turn, and observes a terminal disconnect. It proves the adapters compose over an actual local socket. It does not prove patient-safe standalone persistence or a call from Twilio.

The Node ingress now claims each authenticated provider account and call ID synchronously before awaiting call construction. Concurrent streams, a later webhook with a fresh binding for the same call, and replay after a factory failure cannot create another call owner in that server process during the original three-minute claim window. A closed claim stays in process memory only for that window; a 30-second sweep removes expired claims, and an active claim stays until its socket closes. The claim set is bounded and refuses new calls when full. `E2E-135` exercises those cases over local signed sockets and proves a different call can still start. A later webhook can extend the provider's valid binding beyond the original claim window, so this is not complete replay protection even within one process. The release gate still requires a proven provider fallback and a privacy-safe cross-process admission design.

`TwilioSignedIngress` now requires an independent, static fallback phone number for every dialed clinic number it serves. Its signed webhook returns `<Connect><Stream>` followed by that number's `<Dial>`. [Twilio documents](https://www.twilio.com/docs/voice/twiml/stream) that remaining TwiML executes after the WebSocket closes; [the Dial verb](https://www.twilio.com/docs/voice/twiml/dial) can bridge a still-connected caller to staff. The route is copied at ingress construction, never looked up from Abby's database during a call. Invalid numbers, a destination matching any configured inbound Abby number, and an unknown dialed number fail closed; the latter returns HTTP 503 so a separately configured number fallback webhook can run. `E2E-136` verifies the signed local HTTP response, two distinct clinic routes, loop rejection, and unknown-number refusal. It cannot prove that Twilio actually dials or that an intentional socket close will avoid an unwanted staff dial.

An unavailable primary webhook needs a [Twilio number fallback URL](https://www.twilio.com/docs/voice/twilio-voice-failover-best-practices) hosted independently of Abby; the post-stream `<Dial>` cannot help if Twilio never received its TwiML. A clinic must also prove that the staff destination is reachable, does not route back to Abby, and has an approved normal-call completion path before real traffic. No Twilio number is connected to this code yet.

`createStandaloneClinikoVoiceServer` now composes authenticated `createCall` with the transient voice ledger and OpenAI/Cliniko adapters, and `E2E-138` exercises its signed local socket. A live Twilio signature and media handshake, a phone number, tested provider-owned fallback, live media timing, and durable privacy-safe admission remain open gates. The local socket test does not prove that Twilio will use the configured public WebSocket URL byte for byte in a deployed environment.

The protocol adapter also validates Twilio inbound `dtmf` messages. `E2E-140` proves that an explicitly enabled standalone route sends keys 1 and 2 to the clinic-local today/tomorrow read-only Cliniko path only after the approved greeting has finished. Other keys and keys received during playback or active speech are ignored. The key is exact provider input; no transcription or intent model decision is needed. This local proof does not establish handset behavior or provider fallback in a real call.

`E2E-141` wires the existing lease-renewal loop into the signed call owner. Renewals enter the same serial queue as provider events, so they cannot race a turn transition. A lost lease closes the socket through the ingress callback; the local test proves this after a turn that succeeds beyond the original lease expiry. It does not prove the downstream Twilio `<Dial>` connects staff.
