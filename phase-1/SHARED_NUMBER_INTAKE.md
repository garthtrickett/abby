# Shared-number intake controller

`SharedNumberIntakeService.begin` is the text-testable entry for an authenticated inbound event. It checks the global call key before current routing. An already admitted call returns its original receipt; a pending call returns its captured candidate locations without another host lookup or policy read. A new call identifies its clinic through `ClinicPolicyRouter`. One candidate goes through normal admission. Multiple candidates create a durable pending-location reservation with a two-minute choice deadline. Unknown or ambiguous routes remain typed failures for independent fallback.

`choose(event, selectedLocationId)` accepts only a candidate recorded for that provider call key. It rechecks the current host route and route version before reading the selected location's policy. `CallAdmissionService.bindSelected` then applies the same automation, readiness, and knowledge-snapshot checks as ordinary admission and atomically binds the pending call through the ledger. A different location cannot win a racing choice or claim a bound call. A bound replay returns the original receipt without routing again. The selected location's scope governs all subsequent runtime actions.

Memory and PostgreSQL journeys cover pending replay after host reassignment, unknown-number refusal, invalid and stale choices, disabled automation, concurrent different choices, single-location admission, and an appointment plan that rejects another location's offer. The choice is currently supplied through a trusted synthetic interface. The voice adapter still needs a caller-facing location prompt, an authenticated final-choice turn with one active pre-location session lease, and an independent expiry path. This does not yet complete the live `E2E-055` acceptance case.
