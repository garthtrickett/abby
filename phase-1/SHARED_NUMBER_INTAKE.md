# Shared-number intake controller

`SharedNumberIntakeService.begin` is the text-testable entry for an authenticated inbound event. It checks the global call key before current routing. An already admitted call returns its original receipt; a pending call returns its captured candidate locations without another host lookup or policy read. A new call identifies its clinic through `ClinicPolicyRouter`. One candidate goes through normal admission. Multiple candidates create a durable pending-location reservation with a two-minute choice deadline. Unknown or ambiguous routes remain typed failures for independent fallback.

The host supplies a distinct, bounded spoken name for every location on a shared number. The reservation captures those names alongside the candidate IDs. Missing, duplicate, or malformed names make routing unavailable before any reservation or location policy read. `locationChoicePrompt` renders only the captured names. `chooseFromTurn` resolves a clear final transcript against those captured names and fails closed on other words; it never accepts a separately guessed ID. The lower-level trusted `choose(event, selectedLocationId)` accepts only a candidate recorded for that provider call key. It rechecks the current host route and route version before reading the selected location's policy. `CallAdmissionService.bindSelected` then applies the same automation, readiness, and knowledge-snapshot checks as ordinary admission and atomically binds the pending call through the ledger. A different location cannot win a racing choice or claim a bound call. A bound replay returns the original receipt without routing again. The selected location's scope governs all subsequent runtime actions.

Memory and PostgreSQL journeys cover pending replay after host reassignment, unknown-number refusal, invalid and stale choices, disabled automation, concurrent different choices, single-location admission, spoken-name validation, final transcript choice, and an appointment plan that rejects another location's offer. An [independent liveness scan](PENDING_LOCATION_RESERVATIONS.md) expires abandoned choices. The [pre-location session lease](PRELOCATION_SESSION_LEASE.md) requires one attached session and a clear final choice turn before binding. Playback delivery and media handoff to the bound session remain to be built. This does not yet complete the live `E2E-055` acceptance case.
