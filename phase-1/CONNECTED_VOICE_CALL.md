# Connected synthetic voice call

`ConnectedVoiceCall` owns one authenticated inbound call's synthetic media controller and streamed playback port. The host supplies one event and session ID, ledger, intake and full-session factory, transcription, synthesis, and output adapters. The caller-facing interface starts the call, accepts ordered normalized PCM frames, accepts exact playback-completion evidence, and disconnects. Shared-number location binding and the location-scoped receptionist stay in the existing call coordinator.

After Abby closes a final caller turn, this owner drains eligible durable effects and dispatches the next approved presentation. A location choice binds its scope before a booking turn can use it. A playback completion must match the queued final chunk and commit through the active voice session; if that acknowledgment is lost, the owner checks the exact stored prompt or presentation status before confirming the same evidence on retry. Queue acceptance alone never permits a booking affirmation. A fatal transcription, media, target, startup, or session failure stops media and closes any attached call with a session-close reason; malformed or overloaded frames can be corrected without closing. Disconnect fences output chunks immediately, stops transcription, closes the session, and returns the same terminal state on replay.

Memory and disposable PostgreSQL journeys pass a location prompt, caller PCM, transcription hypotheses, synthesized response chunks, completed playback, affirmation, a keyed host booking, and disconnect through one owner. They also prove that transcription or startup failure closes a pending location without admitting a call, and that disconnect racing admission or a prompt blocks new output. Run `npm test` and `npm run probe:postgres`.

This owner assumes the transport has authenticated its inbound call and playback evidence. It does not implement a telephony codec, real speech provider, number-level fallback, or live transfer. If a bound admission cannot attach a full session, the independent admission monitor still owns eventual closure of that starting receipt. A single-location admission stores a scoped, approved greeting intent before activation. The owner sends it only after activation and records the final playback result; an unactivated call's greeting is superseded by the admission monitor.
