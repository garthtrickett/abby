# Call admission and liveness contract, version 0.1

**Status:** Executable no-number foundation for Phase 1. This is not a live transport, production ledger, or complete voice session.

An authenticated transport event supplies a provider account, provider call reference, dialed number, and event time. `CallAdmissionService.begin` hashes the account and call reference into one global call ID and looks it up **before** asking for current routing policy. A matching replay returns the original receipt without routing again. The same key with a changed dialed number returns `callConflict`; the same provider call reference under another account gets a distinct call ID. Routing exceptions become typed `routeUnavailable` results. The memory fixture uses an injected clock; the standalone PostgreSQL ledger uses its [database clock](LEDGER_CLOCK.md) for admitted-call deadlines and lease decisions.

The ledger stores `starting` and an immutable admission receipt. PostgreSQL stores the receipt and `callAdmitted` event in one transaction. `sessionActivated` changes the call to `active` only before the deadline and issues a versioned 30-second lease with a duration for the local monotonic gate. Renewal requires the current lease version and returns the existing lease for a replay of the immediately preceding version without extending it. Admitted calls accept final turns and presentation starts or results only from the attached session while its lease is valid. A stale session or expired lease receives `leaseLost`. `CallLivenessMonitor` scans at most 100 due admissions and active leases per pass and commits fenced expiry transitions; it can scan all calls or one scoped fixture. Disconnect or lease expiry ends media work, supersedes pending presentations, and marks started presentations `unproven`. Unresolved host and staff effects remain in the call aggregate.

The same tests run on memory and disposable PostgreSQL storage. They cover replay, number conflict, provider-account separation, routing failure, tenant scope, activation, lease renewal and replay, admission and active-session expiry, disconnect, and admission/activation event persistence. Run `npm test` and `npm run probe:postgres`.

The text harness still uses direct `CallRuntime.start` to create an active synthetic call. Live admission uses `CallAdmissionService.begin`. The next slice needs authenticated transport verification, database-clock lease authority, a durable production migration and worker schedule, a delivery dispatcher, media and transcript adapters, a proven provider-owned fallback, and voice E2E evidence. No call is ready for live routing from this contract alone.

The [synthetic admission fallback](ADMISSION_FALLBACK.md) now coordinates new-call failures with an independent provider port and operational alert. Its fake provider outcomes do not establish a live fallback route.
