# Speech-onset revision fence, version 0.1

An admitted voice session records `speechBegan` in the call ledger when a new caller utterance starts. It advances `conversationRevision` and supersedes a pending presentation. It cancels an awaiting action whose presentation was still pending or in progress, while preserving a fully played action so the new utterance can affirm it. A ready or possibly sent host write is left for its existing decision and receipt path. Playback clear starts immediately, and its result is then recorded as interrupted or unproven. The call ends if clearing cannot be proven.

The voice session captures the current conversation revision before resolving an intent or reading host evidence. Its eventual `callerTurn` carries that expected revision. A newer speech onset that commits first makes the older turn fail with typed `staleTurn`. If an older turn commits first, the newer onset supersedes its unsent presentation. The local generation also prevents an older intent result from being reused for the new turn. Direct synthetic text callers can omit the expected revision; their existing contract is unchanged.

The memory and disposable PostgreSQL journeys pause a booking in the host read, start a newer utterance, and prove the old turn creates no action or processed turn. The newer utterance can then create its own action. This is a call-ledger fence for the synthetic session, not proof of real media timing or a complete live dispatcher. The production transport still needs an authenticated ordered event stream, local media-send lease checks, and exact playback completion evidence.
