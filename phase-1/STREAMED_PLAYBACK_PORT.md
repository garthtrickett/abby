# Synthetic streamed playback and per-chunk output gate

One `StreamedPlaybackPort` per live call adapts approved presentation text to normalized mono PCM16LE audio at 16 kHz. A synthesis adapter yields 10–100 ms chunks; an output adapter queues each chunk in order and then queues a final marker. Each provider operation has a deadline, chunks are copied before an asynchronous send, and a bounded chunk count prevents an endless stream. A `queued` return means the final marker was accepted for delivery, not that a caller heard it. Cleared and completed playback IDs remain retired for that call, so a late enqueue cannot revive them.

The voice sessions pass a live output gate into `PlaybackPort.enqueue`. A streaming port checks that gate immediately before every chunk and the final marker. The gate includes the current presentation ID, speech generation, absence of new caller speech, and the conservative local lease. A closed gate aborts synthesis and asks the transport to clear queued audio. Once any chunk may have crossed the send boundary, a failure is `uncertain` even if clear succeeds; only a proven first-chunk refusal returns `notSent`. The transport's `clear` must fence chunks still in flight so they cannot play after a successful clear.

The transport must authenticate a playback-completion event with the exact playback ID and final sequence. `acceptCompletion` rejects early, mismatched, canceled, and duplicate evidence. It invokes a supplied voice-session settlement callback and retains the same evidence for retry if that durable settlement cannot be confirmed. Only a successful voice-session `played` settlement can authorize a later affirmative turn; queue acceptance alone cannot.

Memory and disposable PostgreSQL journeys synthesize chunks for a shared-number location prompt and booking details, reject a premature completion marker, settle exact playback evidence, and prove the later affirmation commits one booking in the chosen location. Focused tests cover copying, per-chunk gating, clear, deadline, first-chunk refusal, and durable-settlement retry. Run `npm test` and `npm run probe:postgres`.

This is a provider-neutral synthetic output path. Real synthesis, authenticated completion callbacks, codec conversion at the output transport, and a proven live clear contract remain required before clinic traffic. A host must route callbacks through `acceptCompletion` and preserve a safe failure route when playback evidence cannot be established.
