# Standalone lit-html dashboard shell, version 0.1

The standalone browser uses direct `lit-html` `html` and `render` calls. A small controller reads permitted capabilities, displays the current booking and after-hours settings, submits versioned changes, and reads a scoped call summary by exact call ID. Templates receive typed UI state and event handlers; they contain no booking or provider rules. The browser fetch adapter handles transport faults and malformed replies as typed failures. The server calls the same `CommandGateway` that agents and an embedded host use.

The generic full dashboard also offers a clinic-admin greeting editor and audit. It accepts exact public text, a version and bounded effective dates, then binds the approval owner to the authenticated actor through `settings.routing.greeting.change.v1`. Disable records a separate setting change and removes the greeting from new call snapshots. `E2E-245` covers the browser and synthetic call behavior, including expired values. The supervised standalone Cliniko panel exposes the same greeting command and audit beside availability setup through a restricted HTTP path; `E2E-246` covers browser, durable listener and signed synthetic voice behavior, including refusal when stored text omits required keypad choices.

`CallReview` projects a call into lifecycle, version, action kinds/statuses, and staff follow-up reasons/statuses. It omits patient references, approved speech, provider payloads, and full call state. The gateway binds the actor's location scope before reading. A clinic administrator may change booking or approve public after-hours information; the after-hours approval owner comes from the authenticated actor. Staff can view settings and call summaries but cannot submit either change command or read admin setting history. Ordinary setting changes affect new calls through their captured policy snapshot. The after-hours control is shown as inactive when live transfer or staff follow-up is unavailable.

Run `npm run demo:dashboard` to start the loopback-only reference dashboard at `http://127.0.0.1:3400` with an in-memory clinic and a synthetic call ID `demo-call`. Run `npx playwright install chromium` once, then `npm run test:browser` for parallel Chromium journeys. The browser journeys cover default, enabled, disabled, page reload, next-call capability, tenant isolation, stale-version refresh, scoped call review, and view-only denial through the HTTP command path. `npm test` and `npm run probe:postgres` cover the typed command and ledger paths separately. Browser E2E runs as its own parallel CI job.

The dashboard also has a separate lit-html clinic availability setup panel when its bound actor has `clinic.availability.approval.change.v1`. It lists business metadata, inspects one practitioner/type selection, shows the stored approval version, requires explicit confirmation of read-only use, and can approve or revoke the route. Its current-route check reuses call-time route, policy, credential and selected Cliniko catalogue validation and reports a point-in-time eligibility result; every call still rechecks. The local HTTP endpoint accepts its availability setup commands and the public greeting approval/audit commands through the same schema-checked gateway; it requires a loopback socket, exact loopback Host, and same-origin request. `E2E-195` and `E2E-216` cover the browser flow against a synthetic Cliniko catalogue. A stored approval grants no patient action or staff request.

The demo binds a fixed local actor and has no production authentication. `createHostAuthenticatedDashboardServer` is the embedding boundary: the host resolves an actor from its own authenticated session for every request, creates a `CommandGateway` for that exact actor, and supplies a fixed public origin. Abby rejects absent identity, mismatched gateway identity or Host, and POST requests without that exact Origin. No role, tenant or actor value from request JSON or self-declared role headers grants access. `E2E-211` covers this boundary with synthetic host sessions. `createStandaloneClinikoAdminDashboard` composes that boundary with the standalone privacy preflight and durable Cliniko route approval; `E2E-212` proves a separate signed voice runner reads an admin approval and rejects a call after revocation. A deploying host must still select and integrate a real identity source, deploy the appropriate listener, and implement the broader call-review and staff-work screens before clinic use. The local demo uses no live Cliniko data or media and has no Cliniko setup port, so its availability panel stays hidden.

For a supervised owner-only setup rehearsal, set `DATABASE_URL`, the same `ABBY_TENANT_ID`, `ABBY_CLINIC_ID`, `ABBY_LOCATION_ID`, `ABBY_TWILIO_ACCOUNT_SID`, `ABBY_TWILIO_TEST_NUMBER`, `ABBY_VOICE_ROUTE_VERSION`, `ABBY_CLINIKO_API_KEY` and `ABBY_CLINIKO_CONTACT_EMAIL` as the intended voice runner. Set a distinct random 64-character lowercase hex `ABBY_ADMIN_ACCESS_TOKEN_HEX` and an opaque `ABBY_ADMIN_ACTOR_REF`; `ABBY_ADMIN_PORT` defaults to `3401`. Run `npm run admin:local` and open `http://127.0.0.1:3401` on the same machine or through an SSH tunnel. At the browser challenge, use username `abby-admin` and the admin token as the password. The listener binds only `127.0.0.1`, loads the dedicated lit-html bundle, exposes availability setup, public greeting approval and audit, settings read, aggregate speech status and clinic-scoped seven-day operational counts over HTTP, and keeps the token, Cliniko key, transcripts and owner-only report paths out of the browser response and Abby database. Keep the token in an owner-only environment file, outside shell history and chat. `E2E-214` checks the local challenge, browser route approval/revocation and durable restart readback with synthetic data; `E2E-246` checks the greeting panel and durable approval/disable. `E2E-233` checks the speech status role boundary, redacted browser response and unavailable-evidence fallback. `E2E-235` checks the admin-only, actor-scoped operational read, malformed-result refusal and PostgreSQL restart readback. The speech panel reads the current owner-only report set through `readSpeechGateStatus`; missing, invalid, stale or insecure reports show unavailable and release unverified. A synthetic placeholder number can rehearse setup before a Twilio number exists; approval must be repeated for the final exact route. This local token does not establish a real clinic staff identity or clinic sign-off.

The panel reports whether the current Cliniko business catalogue could be checked and compares its credential fingerprint with the stored approval. After changing `ABBY_CLINIKO_API_KEY`, restart the local admin listener with the new key, inspect the selected business/practitioner/type, and record a new approval version before testing another call. A stored approval from the old key remains visible for audit but is inactive at signed call admission. `E2E-215` covers the browser warning and the signed refusal/reapproval sequence with synthetic credentials. A matching fingerprint does not certify current appointment availability or clinic sign-off.
