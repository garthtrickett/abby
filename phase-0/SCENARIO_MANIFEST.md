# Scenario manifest, version 0.3

[SCENARIO_MANIFEST.json](SCENARIO_MANIFEST.json) tracks the 150 stable E2E IDs in [Technical Design Section 11](../TECHNICAL_DESIGN.md#11-verification-design). The design table owns each journey's wording; the registry adds its requirement mapping, fixture family, intended compositions, earliest implementation phase, and evidence status. Each scenario's fixture ID is `fixture-` plus its lowercase E2E ID. The capability and setting maps cover the current agent catalogue and its three behavior settings. `test/contract/scenario-manifest.test.ts` checks the design and catalogue for drift, duplicate or missing IDs, and test-file references.

Every `fullCallEvidence` entry is **planned**. Existing text, browser, provider-contract, and synthetic voice tests are valuable evidence, but none proves the complete full-call scenario with the required production entry point and transport observations. `E2E-125` through `E2E-127` record passing **text-only** evidence from availability, startup refusal, and configuration portability journeys. `E2E-128` through `E2E-146` record passing **synthetic voice** evidence for speech generation, playback acknowledgment, Realtime transcription, Twilio media protocol handling, signed Twilio ingress, a local socket through Abby's actual call owner, transient presentation content, a disposable standalone voice ledger, process-local stream replay refusal, static post-stream fallback routing, transient availability intent selection, the composed standalone server, one bounded clarification before fallback, a clinic-approved keypad availability route, live-call lease renewal with terminal socket closure, greeting interruption through a returned clear fence, startup refusal of unsafe storage, a host-owned embedded voice call, a keyed embedded voice booking after exact playback and affirmation, and correlation of an early Realtime final with its later commit acknowledgment. `E2E-147` adds a passing text journey for a Cliniko slot returned on the wrong clinic-local date. `E2E-148` adds synthetic voice evidence for interchangeable host-owned availability ports in the embedded composition. `E2E-149` adds a signed local socket through a buyer-process embedded voice composition and a host-owned diary. `E2E-150` adds a bounded synthetic speech loop with missing safety-word detection; a separate opt-in run exercises the live synthesis and transcription adapters. All remain planned for full-call evidence. `fixtureState` describes only the named fixture's current implementation level, not release approval.

Before P0-09 can close, each planned fixture needs explicit inputs and observed caller, host, ledger, and staff assertions; independently triggerable failures need separate fixtures. Typed failure kinds still need scenario mappings. The first Phase 1 slice must add real full-call test files and change their manifest entries in the same pull request, while clinic and provider gates remain governed by the support matrix. A new feature or setting must add or extend its E2E ID and test at the same time; this registry alone does not make an untested feature releasable.
