# Phase 0 Cliniko evidence

**Status:** Discovery in progress. Documentation evidence is separate from account-probe evidence. Synthetic demo writes have been exercised; no live capability is yet classified executable.

**Account profile:** User-supplied demo account; API key and login credentials are excluded from this repository. Probes print only the shard, HTTP statuses, aggregate counts, and synthetic cleanup outcomes. A safe-write conclusion requires more than a successful account mutation.

The approved support matrix is a later Phase 0 output. A documented endpoint or successful GET does not promote any mutation to executable support. No mutation probe runs until its synthetic fixture, expected after-state, and cleanup/reconciliation method are written down.

## Read-only account probe

Run `python3 phase-0/probes/cliniko_readonly.py` in an interactive terminal. The script prompts for a contact email and hidden API key, makes four allowlisted metadata GET requests and up to two bounded available-time GET requests, and prints only HTTP status, aggregate counts, and online-booking booleans. It does not read from an environment file, persist credentials, or print API response records. A 404 offer probe makes its process exit nonzero while preserving the successful metadata results.

**Result:** C-LIVE-01 and C-LIVE-02 above. The later controlled probes C-LIVE-03 and C-LIVE-04 established the effect of the business setting and basic synthetic write permissions. Do not infer safe automated mutation from these results.

## Controlled synthetic probes

Run `python3 phase-0/probes/cliniko_availability_probe.py` to temporarily enable online booking, read available times for a date in the business's local time zone, invoke the actual TypeScript adapter for each type, and restore the original business flag. Run `python3 phase-0/probes/cliniko_write_probe.py` for one synthetic patient and appointment, exact marker lookup, a direct time update, cancellation, patient archive, and business-flag restore. Both prompt for the key without echo and print statuses and counts, not response records. The write probe does **not** retry an uncertain POST. If a cleanup result is uncertain, stop writes and run `python3 phase-0/probes/cliniko_cleanup_verify.py`; that read-only script includes cancelled and archived views. A cancelled appointment remains in Cliniko's audit history and is absent from the ordinary appointment view.

Run `python3 phase-0/probes/cliniko_concurrent_booking_probe.py` only in the sanctioned demo account. It submits two marked synthetic appointments at the same available time in parallel, reconciles by patient and marker, cancels every located appointment, archives the synthetic patient, and restores the original business flag. A zero exit code means the probe and cleanup completed, **not** that concurrency is safe. C-LIVE-07 records the observed duplicate acceptance and independent cleanup verification. The script does not retry a failed or uncertain POST.

The write probe now invokes `cliniko_appointment_adapter_probe.ts` while its synthetic appointment is active. It checks exact appointment count and the configured business time zone, prints only the comparison result, and then follows the same cleanup path. C-LIVE-06 records the first positive adapter run and the separate cleanup verification.

Run `python3 phase-0/probes/cliniko_patient_candidate_probe.py` for two isolated marked synthetic patients with the same email and date of birth. It invokes the TypeScript reader after each create to check one then ambiguous results and a wrong-birth-date miss, archives both patients, and verifies their archived views. It prints only statuses and result kinds. C-LIVE-08/09 record the controlled runs. Do not treat a returned candidate reference as a verification reference.

Run `python3 phase-0/probes/cliniko_staff_work_readonly.py` to inspect only aggregate counts and HTTP status for recall types, recalls, and communications. In the sanctioned demo account, `python3 phase-0/probes/cliniko_recall_work_probe.py` creates one marked synthetic patient and uses the TypeScript one-attempt writer to create a recall under an existing active recall type. It reads the exact patient-scoped marker through both the direct probe and TypeScript reader, marks it recalled, and archives both fixtures. The reader checks both active and archived reads; no uncertain create is retried. If cleanup is uncertain, stop mutation probes until the account is inspected. C-LIVE-11/13/15 record observed runs and separate read-only checks for zero active recalls. A successful recall write is not a staff-delivery receipt.
